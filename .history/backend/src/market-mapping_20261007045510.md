# Gate Market-Data Mapping

| Product        | REST source                                                                                    | Public WebSocket                                                                                                            | Paper-specific behavior                                                                                |
| -------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| USDT perpetual | `/futures/usdt/contracts`, `/futures/usdt/contracts/{contract}`, `/futures/usdt/order_book`    | `wss://fx-ws.gateio.ws/v4/ws/usdt`; `futures.book_ticker`, `futures.trades`, `futures.order_book_update`, `futures.tickers` | Uses exchange mark/funding fields when present; fills are local estimates                              |
| USDT delivery  | `/delivery/usdt/contracts`, `/delivery/usdt/contracts/{contract}`, `/delivery/usdt/order_book`, `/delivery/usdt/trades` | Public REST polling every 2 seconds; no delivery channel was found in Gate's maintained SDK                | Direct (linear) contracts only; no perpetual funding; settle only with a positive Gate `settle_price` |
| Options        | `/options/underlyings`, `/options/contracts`, `/options/tickers`, `/options/order_book`        | No Options WebSocket channel was found in Gate's published `gatews` SDK/docs at implementation time                         | Market data refreshes by REST; premium and expiry settlement rules require contract-level verification |

The Futures WebSocket URL and channel names are from Gate's maintained [`gatews` SDK](https://github.com/gate/gatews). The local Futures book buffers depth deltas while refreshing a REST snapshot after a sequence gap, then replays updates that bridge the snapshot ID. Options and delivery use public REST polling because their channels were not found in the maintained SDK. No private or authenticated exchange endpoint is used.
